# 과제 5 고정 검사

## 검사 대상

Afterwave 접근 로그 화면의 다중 조건 필터 기능을 검사한다.

## 고정 원칙

* 아래 검사는 AI A 작업 시작 전에 고정했다.
* 검사 수는 정확히 10개다.
* AI A와 AI B는 동일한 검사를 실행한다.
* 검사 ID, 입력, 기대값을 변경하지 않는다.
* 검사를 삭제하거나 조건을 완화하지 않는다.
* 구현 결과에 맞춰 기대값을 변경하지 않는다.
* 최초 화면에 표시된 전체 로그 건수를 `N`이라고 정의한다.

## 고정 검사 10개

| ID    | 입력                                     | 관찰 가능한 기대값                               |
| ----- | -------------------------------------- | ---------------------------------------- |
| FT-01 | 필터를 입력하지 않고 접근 로그 화면에 접속한다.            | 전체 로그가 표시되고 결과 건수는 `N`이다.                |
| FT-02 | 사용자명 검색창에 `kim`을 입력한다.                 | 표시된 모든 로그의 사용자명이 `kim`이며 결과가 1건 이상이다.    |
| FT-03 | 사용자명 검색창에 앞뒤 공백과 대문자가 포함된 `KIM`을 입력한다. | 공백과 대소문자를 무시하고 FT-02와 같은 결과가 표시된다.       |
| FT-04 | 자원 필터에서 `hr-system`을 선택한다.             | 표시된 모든 로그의 자원이 `hr-system`이다.            |
| FT-05 | 판정 필터에서 `ALLOW`를 선택한다.                 | 표시된 모든 로그의 판정이 `ALLOW`다.                 |
| FT-06 | 최소 위험도에 `15`를 입력한다.                    | 표시된 모든 로그의 위험도 점수가 15 이상이다.              |
| FT-07 | 사용자명 `kim`과 판정 `ALLOW`를 동시에 적용한다.      | 두 조건을 모두 만족하는 로그만 표시된다.                  |
| FT-08 | 사용자명 검색창에 `no-such-user-999`를 입력한다.    | 결과 건수는 `0`이고 `조건에 맞는 로그가 없습니다` 문구가 표시된다. |
| FT-09 | 하나 이상의 필터를 적용한 뒤 초기화 버튼을 누른다.          | 모든 필터 입력값이 초기화되고 전체 `N`건이 다시 표시된다.       |
| FT-10 | 사용자명 `kim` 필터를 적용한 상태에서 페이지를 새로고침한다.   | 새로고침 후에도 사용자명 입력값과 필터 결과가 유지된다.          |

## 검사 실행 결과 표기

각 실행 회차는 다음 형식으로 기록한다.

| 실행 주체 | 실행 회차 | PASS 수 | FAIL 수 | 첫 실패 검사 |
| ----- | ----: | -----: | -----: | ------- |
| AI A  |     1 |        |        |         |
| AI A  |     2 |        |        |         |
| AI B  |     1 |        |        |         |
| AI B  |     2 |        |        |         |

오류 회차는 고정 검사 10개 중 하나 이상이 FAIL인 실행 회차로 계산한다.
